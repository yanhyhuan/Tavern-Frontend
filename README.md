# Tavern Frontend

**数据库 骰子系统 · V1.0.1**

> 固定测试发布：已完成自动回归；真实 TauriTavern 重开聊天尚未实测，在途切聊仍存在跨聊天误写风险。当前版本没有通过全部验收，详见下方已知边界。

基于 `jerryzmtz/my-tavern-scripts v6.32` 制作的酒馆扩展，保留原骰子界面和功能，修复与龙血玄黄数据库 1.3.6 的模板检查及正则保存兼容问题。数据库继续使用原版，运行仍需酒馆助手。

## 安装

1. 先在旧骰子界面导出配置方案备份，再备份并停用酒馆助手中的旧「数据库前端·骰子系统」脚本；保持数据库及酒馆助手启用。
2. 在酒馆的扩展管理中选择「安装扩展」，输入：

   ```text
   https://github.com/yanhyhuan/Tavern-Frontend
   ```

3. 启用「数据库 骰子系统」并刷新酒馆。扩展根目录已经包含构建产物，无需安装 Node.js 或自行编译。

如果客户端没有仓库安装入口，可下载 `V1.0.1` Release 的 ZIP，将解压后的 **Tavern-Frontend** 文件夹复制到 TauriTavern 数据目录的 `data/extensions/third-party/`，再启用并刷新。请确认 `Tavern-Frontend/manifest.json` 直接存在，避免多嵌套一层文件夹。

检测到启用的旧骰子脚本或已有实例时，扩展会停止并提示；停用旧脚本后刷新即可。此版固定在 `V1.0.1`，不自动追踪原项目最新标签。

## 内置模板和预设

打开原界面中的「设置 → 高级设置 → 内置表格模板」，可以选择并下载完整模板：

| 模板 | 用途 |
| --- | --- |
| 数据库默认 1.3.6（默认基线） | 数据库原版自带的 8 张表；本扩展内置预设按这套结构适配。 |
| runtime SQL v4.5（可选兼容） | 12 张表，来自维护者提供的模板；保持其 key、uid、DDL 和规则。 |

两份模板都只有表头，没有聊天数据行。旧骰子 v4.3 模板已退出运行资源和默认配置。下载不会自动导入、重建或替换已有表；已有模板检查正常时无需重新导入。新建测试聊天时，可按数据库自身的模板导入流程使用。

继续使用现有 v4.5 聊天时，在「模板检验预设」选择「v4.5 模板检验」，保留其原有 12 表。数据库默认 8 表是新建聊天及内置预设的设计基线，两套模板分别使用对应的检验预设。

检定 6 组、属性生成 2 组、交互/渲染/仪表盘预设、模板检验、数据验证和表格正则，以及商城 6 卡池和 95 件物品均继续内置。默认配置以数据库自带 8 表为基线：任务进度保留叙事文本，物品和装备进入默认背包，校验与正则使用真实表头。具体清单见 `assets/presets/README.md`。不会把维护者的私人聊天配置打包进来。

内置正则包含自动执行规则；其默认作用域限定在叙事/关系字段，避开姓名、row_id、数量、时间和编号。首次测试请使用合成聊天，并先核对规则开关。已有配置和自动规则会按原前端逻辑运行。

默认模板没有数值属性专列。属性生成、燃运和成长使用扩展自己的聊天属性，按聊天、隔离环境和稳定角色身份保存；不占用“近况”或“等级/阶段”等叙事字段。它们保存在本机浏览器存储，与数据库聊天导出是两个数据范围，跨设备前请另行导出扩展属性。v4.5 若有属性专列，继续使用公开 CRUD 保存到原列。

属性备份入口位于「配置方案与备份 → 当前聊天属性备份」。恢复要求聊天、角色/群组、隔离环境及角色的 key、uid、row_id 与原环境一致，并尊重行锁；其他聊天的数据不会自动套用。清除浏览器存储也会删除本机属性，请保留导出的备份。脚本接口见 `src/骰子系统/docs/API.md` 中的 `exportChatAttributes()` 和 `importChatAttributes()`。

地图可以从全局和角色的既有位置生成只读地点概览；未记录地区的地点归入“其他”，不会编造地图表或探索状态。默认背包没有品质列时，骰子新奖励的稀有度随“描述/效果”中的 `【骰子品质:…】` 标记保存。默认模板没有独立检定建议表，六套检定和数值输入仍可使用；该表专用的 AI 建议按钮不作为默认表结构的要求。

## 本版修复

- 模板检查和修复候选共用逻辑表匹配。显示名或明确别名唯一、业务列兼容时，允许稳定 key 和 SQL 物理表名与默认模板不同；真实缺列、歧义和约束冲突仍报告。
- 已有表保持原样。缺表时只导出新增表候选片段，避免整模板导入改动已有配置；同名不兼容时停止，不继续创建重名表。
- 正则转换保留 `row_id`，只通过原数据库公开 CRUD 更新变化的单元格，移除旧聊天 JSON 保存及失败回退。API 拒绝、部分成功、环境切换或读回不一致均明确报错。
- 正则成功确认同时检查公开运行态、公开历史回放、宿主已保存副本及非目标行/表；互相抵消的规则报告没有净变化，不假称保存成功。
- 原界面直接运行在宿主页面；桥接隔离本扩展的监听、日志和错误处理，避免覆盖酒馆的全局处理器。

切换检定或属性预设只修改骰子配置，不再为同步规则说明而隐式整模板导入。已有表、字段及 note 保持原样。

## 验收与已知边界

各功能适配范围见 `docs/FEATURE-COMPATIBILITY.md`；已完成的合成与源码集成验证见 `docs/TESTING.md`。真实 TauriTavern 安装、全部原功能和关闭后重新打开聊天的持久化仍需实机验收，不能用当前界面显示替代。

原版数据库的公开 CRUD 没有预期聊天、预期行或取消参数。前端会拦住排队任务和后续写入，并检测部分并发副作用，但无法撤销已经进入数据库内部的调用。**保存期间请等待结束再切换聊天，避免同时编辑同一单元格。** 在途切聊仍有跨聊天误写风险，因此“任意切聊下零跨写”这项验收没有满足；合成宿主已复现风险，真实源码确认存在竞态窗口，尚未在真实客户端复现。原库真实集成测试还确认：新 AI 楼层尚无表帧时，手工 CRUD 可以追加到较早的已有表帧，改变该楼层的历史回放；本扩展不通过改写私有历史来绕过这项语义。

测试脚本位于 `diagnostics/`，其中可导入酒馆助手的 JSON 默认停用：

- 「只读测试」检查已启动的固定版扩展和公开 API，不执行数据库写入。
- 「加载测试」从固定的本地安装路径加载扩展，模块在宿主页面执行。请在合成聊天运行，扩展启动后可能按当前配置执行自动规则。

它们都不代替重开聊天验收。

## 目录与构建

```text
manifest.json / index.js / loader.js / bridge.js / dice.js  扩展运行文件
src/骰子系统/                                            原前端源码及兼容补丁
assets/templates/                                       完整内置模板
assets/presets/                                         内置预设清单
scripts/                                                构建、打包与补丁生成
tests/                                                  合成回归和原库集成用例
diagnostics/                                            酒馆助手测试脚本
docs/                                                   验收记录与操作说明
patches/                                                原骰子核心及模板相对 v6.32 的 diff
```

开发环境：Node.js 24、pnpm 10.28.2。

```powershell
corepack pnpm@10.28.2 install --frozen-lockfile
corepack pnpm@10.28.2 test
corepack pnpm@10.28.2 lint
corepack pnpm@10.28.2 typecheck:compat
corepack pnpm@10.28.2 build
corepack pnpm@10.28.2 package
```

本仓库 `package.json` 的 `build` 调用 `scripts/build.mjs`，复用上游 webpack 配置编译原骰子系统，再封装根目录 `dice.js`。上游原始构建命令为 `webpack --mode production`。未包装 bundle 和 source map 位于忽略的 `.build/`；ZIP 位于 `release/`。ZIP 打包步骤使用 Windows PowerShell。

`patches/dice-v6.32-V1.0.1.patch` 记录原骰子 `src/骰子系统` 和模板资源的变化，并检查可应用于固定 v6.32 提交。新增的扩展入口、桥接和构建脚本直接保存在仓库根目录及 `scripts/`，完整源码随 ZIP 交付。

## 回滚

先导出本扩展的独立聊天属性，再停用或移除此扩展及测试脚本，刷新酒馆，启用之前备份的旧骰子脚本并恢复升级前的配置方案。旧脚本不能读取本扩展的独立属性，保留其备份以便重新启用本扩展时恢复。数据库安装和原模板文件没有被修改。回滚代码不会撤销已经成功保存的单元格；数据恢复请使用自己的聊天备份。
