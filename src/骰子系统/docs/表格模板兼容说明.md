# 表格模板兼容说明

骰子系统 V1.0.1 以龙血玄黄数据库 1.3.6 的原版 8 表作为默认模板检验基线：全局数据表、主角信息表、重要角色表、主角技能表、背包物品表、任务与事件表、纪要表和选项表。设置中另可下载并选择 v4.5 的 12 表兼容模板；两份完整模板只下载，不会自动导入或替换当前表格。

## 检查和缺表候选

检查和候选计划使用相同的表身份规则：稳定 key、唯一显示名或明确的 `sourceData.tableAliases` 可以识别同一逻辑表。key 和 `CREATE TABLE` 物理表名不同不代表缺表；业务列、DDL 类型和约束仍需兼容。

- 同名或别名匹配但缺列、DDL 不兼容、名称或别名歧义时，报告冲突并停止生成候选，不修改已有表。
- 数据库按表名拼音生成物理名；不同表名映射到同一物理名时也会报告冲突，停止整批候选。
- 确实缺少内置表时，生成保留该版本原始列、DDL 和规则的新增表候选；`uid` 非空且等于新 key，首列为 `row_id`。
- 候选只是新增表片段，不是完整模板。请核对后在数据库中手动添加并由数据库校验；自定义预设的缺表也需手动添加。
- 现有表的 key、uid、名称、列、DDL 和数据不会被调整。重复检查或生成候选不会不断添加相同表。

数据库完整表的首列应为 `row_id`；数据库接受首列 `null` 作为其占位。其他列和表名须满足数据库的名称与唯一性约束。检验结果里有冲突时请先人工处理，不要通过整库导入覆盖现有聊天。

## 默认表与功能

默认背包统一记录物品和装备，实际列为 `物品名称`、`数量`、`描述/效果`、`类别`；任务进度是叙事文本。默认主角表和角色表没有数值属性列，也没有独立地图、装备、检定建议或品质列。需要相应功能时可使用扩展自己的属性配置、现有位置的只读概览，或明确选择适合玩法的模板；不能假设这些表和列已经存在。

关系图从重要角色表读取 `姓名` 和 `人际关系`；主角如需提供自己的关系，`主角信息表` 或旧名 `主角信息` 还需有 `人际关系` 列。切换骰子预设不会为了同步规则而隐式修改数据库模板 note。

正则自动转换通过数据库公开 CRUD 保存实际变化的单元格，并检查保存结果；不写旧 JSON 楼层或私有 `storageFrame`。公开 API 没有原子取消参数，保存尚未结束时应等待完成再切换聊天。

更多功能边界和验证范围见项目的 `docs/FEATURE-COMPATIBILITY.md` 和 `docs/TESTING.md`。
